# Metrics and honest attribution

All processing/resource measurements use wall time, independent of LineSimulation.Time. Source time/sequence/session belong to the simulated PLC.1Hz sampling, bounded display histories;5s/300-sample render distribution,200recent records plus60persisted review events. Model loaded/available is not actively processing; selected/actual vision device and idle/processing shown separately. Qwen residency does not establish activity; application request state is explicit.

- Host CPU: delta /proc/stat busy over total ticks across all32logical processors;100%means all processors fully busy, initial sample N/A.
- Backend and native CPU: delta process CPU ticks/(wall seconds ×CLK_TCK), one logical CPU=100%; may exceed100%for multithreaded work. RSS from /proc/PID/stat, decimalMB. Process residency includes shared libraries; do not add it to separate GPU accounting as physical consumption.
- GPU busy: readable amdgpu card/device/gpu_busy_percent, whole device including Unity, vision, Qwen, desktop and other processes. No exact per-process GPU allocation or pie chart.
- Temperature: amdgpu hwmon temp1_input if present; Celsius sensor value, not each component’s temperature. RAM available: /proc/meminfo MemAvailable, GiB. Unavailable values N/A. No sum of overlapping shared-memory domains.
- Rendering: native frame intervals from unscaled Unity updates, target60FPS/VSync0/4MSAA; measured FPS reciprocal of mean interval. Percentiles are intervals, not guaranteed display refresh/deadlines. Exported frame CSV preserves startup; comparable run excludes first10s.
- Captured: one shared-bottle batch with three camera frames. Camera refresh/render is not completed inspection. Completed inspections=individual results including uncertain; per-class outcomes separate. Rate completed/window. Queue depth in batches;2queuedbatches plus at most one active batch; dropped and missed2s deadlines explicit.
- End-to-end: native capture UTC before first scene render/PNG encode → service result completion UTC; includes readback/encoding/HTTP/parse/crop/save/queue/preprocessing/inference/policy. Assumes same host clock stable. Queue: accepted work timestamp → station processing start, includes earlier station processing within same batch.
- Preprocessing: RGBconversion/bilinear24×24/float32 array creation. CPU inference: dense/ReLU/dense/softmax work; policy/result overhead reported in total classifier time. GPU transfer: buffer creation/upload and synchronous readback wall time; it includes waiting for GPU completion, so cannot be added to GPU timer as independent elapsed work. GPU shader elapsed: hardware GL timer query for two dense dispatches, barriers; measured GPU execution. GPU inference wall time excludes accounted transfer calls; command submission/driver overhead remains. Small values are not calibrated reliability confidence or exact GPU utilisation share.
- Cold load: NumPy weight load and GPUcontext/shader/buffers startup recorded separately. First prediction may compile/initialise driver work;10s native warm-up excluded.
- Replay: same saved validation crops/weights/preprocessing/thresholds, one bounded worker/2batchqueue, fixed rates2/10/50/100 batches/s,10s/step,stopatfirstoverflow/deadline. Excludes Unity/camera/HTTP/evidence writes. Not additional cameras or real line capacity. Monitoring comparison uses same replay with/without1Hz counters; short variation is not guaranteed zero overhead.

Quality timing/stats describe this synthetic demo only. Existing services preserved, background process names recorded; no driver/power/tuning change. Interference from host activity remains possible. Measured visionCPU/GPU comparison uses the same neural artifacts; old RF and Gemma use different images/models and are separate historical baselines.

Camera count denotes three configured inspection views, rendered together only on a bottle trigger; no continuous30FPS inspection stream. Pause/disabled captures perform no new inspection. Current Debug history may include startup or screenshot overhead; use saved warmed benchmark intervals for performance comparisons.
